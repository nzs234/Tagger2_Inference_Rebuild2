# Tagger2 V1.05 Release Notes

V1.05 adds a BooruDatasetTagManager-style **tag management workspace** and
delivers a full correctness/performance/refactoring pass across the backend.
The pinned Dataset Workflow baseline is unchanged: the byte-identical upstream
ports (`caption_format/normalizer.py`, `caption_format/flat_txt.py`,
`stages/replacement.py`, `raw_e621.py`) and the frozen nine-field order are
exactly as before, guarded by the same port-manifest tests.

## New: Tag Manager (标签管理)

A dataset tag editing workbench for e621 and danbooru datasets; details in
`docs/tag_manager.md`.

- Dataset sessions: open any registered input root with a relative path,
  background indexing with progress, mtime-based incremental refresh, stable
  image ids across rescans, multiple concurrent sessions.
- Grid browsing: windowed thumbnail grid with tag-count and sidecar badges,
  sorting by name/mtime/tag count, tag-combination filters (include all/any,
  exclude), sidecar-format filters.
- Editing in three formats with format-native editors: booru flat TXT, the
  local tags JSON container (category/score metadata preserved), and the
  nine-field standard JSON (field-by-field form). Raw e621 grouped JSON is
  read-only. Saves are atomic writes guarded by a sidecar-mtime optimistic
  lock (`409 sidecar_conflict` on external changes).
- Batch operations: add/remove/replace tags (regex supported) across a
  multi-selection or the current filter; nine-field documents are only touched
  in their `tags`/`appearance`/`environment` list fields.
- Undo/redo: per-session operation journal (last 20 steps) replays exact
  before/after sidecar content.
- Tag database autocomplete backed by the existing workflow classify-snapshot
  resources: category colors, post counts and alias resolution. e621 works out
  of the box; danbooru activates after importing an official export with
  `scripts/import_classification_snapshot.py --profile danbooru`.
- Tag frequency statistics, server-side cached thumbnails with decode budgets,
  isolated SQLite index under `data/tag_manager/`.

## Correctness fixes

- **Workflow NL adapter event-loop leak**: the NL stage no longer creates a
  fresh event loop per request (which stranded pooled httpx connections and
  leaked the provider). The adapter owns one dedicated loop, closes the
  provider deterministically when the job run finishes, and supports bounded
  per-job concurrency (`nl.concurrency`, default 4).
- **Image-generation family inference**: prefixed proxy aliases such as
  `firefly-gpt-image-2` now resolve to the GPT-image family in `auto` mode
  (boundary-aware match), making the uncommitted custom-size specialization
  actually reachable; the `response_format` strip uses the same matching and
  retry delay caps are unified at 120 s.
- **Unsafe pickle fallback tightened**: `weights_only=False` is now only
  attempted for genuine torch weights-only rejections, not for arbitrary
  load errors (OSError, truncated files, ...).
- **Failure visibility**: the global 500 handler, provider connection tests,
  workflow cleanup clusters and aesthetic-classifier failures now log tracebacks
  instead of passing silently.
- Assert-based internal invariants replaced with explicit raises that survive
  `python -O`; the update-script test now passes on localized Windows
  installations.

## Performance

- Blocking DNS validation is cached (5-minute TTL); the image-generation
  client validates once per request instead of twice per retry attempt.
- Directory scans, job-item persistence, workflow restore/discard/preflight
  and image-generation deletion run off the event loop via `asyncio.to_thread`.
- Job counters update incrementally per item transition with a full
  reconciliation at terminal states (was a full-table aggregate per image);
  profile listings and SSE event streams no longer open a connection per row
  or per poll.
- The VisionProvider cache is LRU-bounded (8) and keys on the stable profile
  identity, so per-job snapshots no longer multiply never-evicted provider
  instances; workflow caption predictions run in batches (default 8) through
  the engine batch API with per-image fallback.

## Refactoring

- `workflow/pipeline.py`: the ~1,380-line `_run_offline_pipeline_impl` is now a
  78-line orchestrator over 20 explicit phase functions with a frozen
  `PipelineContext` / mutable `PipelineState`; the duplicated nine-field
  projection builds were unified.
- `workflow/api.py`: the ~2,400-line router factory is split into a 136-line
  factory plus ten focused route modules; route table and OpenAPI schema are
  verified byte-identical against the previous release.
- `main.py`: 2,998 → 1,898 lines; job processors and user-settings persistence
  extracted to `processors.py` / `user_settings.py`.
- Shared helpers (`utc_now`, `canonical_json`, hashing, OOM handling)
  consolidated into `common.py`; provider shim duplicates collapsed; the dead
  `TaggerInference` facade removed.
