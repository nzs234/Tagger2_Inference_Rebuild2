# Tagger2 V1.04.1 Release Notes

V1.04.1 is a deployment reliability patch for the V1.04 multi-provider image
generation release. Application behavior and the pinned Dataset Workflow
baseline are unchanged.

## Portable runtime fix

- Fixed a fresh base-runtime ZIP failing with `No module named pip` during its
  first dependency installation.
- `setup.bat` now checks whether pip is actually importable instead of treating
  an existing `get-pip.py` file as proof that pip is installed.
- `start.bat` now performs the same bundled pip bootstrap when it is launched
  directly, so both documented and direct startup paths recover correctly.
- Pip bootstrap is pinned to `pip==26.1.2` before the hashed CPU or CUDA lock is
  installed.

## Release validation

- Base-runtime packaging removes stale dependency markers after stripping
  `site-packages` and `Scripts`.
- The release build fails if the portable pip bootstrap is absent.
- Automated tests cover the setup/start bootstrap contract, and extracted
  package smoke checks cover the clean base-runtime layout.
- The final ZIP is additionally deployed in a newly created empty directory,
  installed from its bundled runtime, started, queried through its HTTP API,
  stopped and started again before publication.

## Upgrade notes

- V1.04 ZIP users should install V1.04.1 into a new directory rather than
  modifying the old extracted runtime.
- Git checkouts can use `update.bat`; it performs only a clean fast-forward.
- Provider keys, generated images, models and local task databases are not
  included in the release package.
