# Tagger2 V1.10 Release Notes

V1.10 adds a fully offline E621 Tag Wiki: a local mirror of the official
e621 wiki pages with cross-lingual semantic search, structured Chinese
summaries for popular tags, and retrieval-augmented AI Q&A through the
already-configured online providers. The pinned Dataset Workflow baseline is
unchanged.

## New: local Tag Wiki page (`/tag-wiki`)

- **查含义 (lookup)** — a tag name resolves through alias normalization to the
  full wiki page: English sections, the structured Chinese summary, implied
  pairing tags and related wiki links. A drawer version of the same view opens
  from the tag manager grid/pills and the workbench tag cloud via the
  查看 Wiki buttons, and both the tag manager sidebar and the display bar
  gained a direct wiki lookup form.
- **语义搜索 (search)** — Chinese or natural-language descriptions hit the
  English corpus through `intfloat/multilingual-e5-small` ONNX embeddings
  (384-dim, `query:`/`passage:` protocol) fused with SQLite FTS5 keyword
  matches via Reciprocal Rank Fusion; results carry wiki evidence, scores and
  suggested tags.
- **AI 问答 (ask)** — retrieved chunks plus summaries become grounded context
  for the configured online LLM (the same providers as the tagging channels);
  answers must cite what the wiki actually says and recommend tags that exist
  in the retrieved material. Without a configured provider the page shows the
  familiar 409 setup state instead of failing.

## Build pipeline and data hygiene

- Data comes from the official e621 `db_export` wiki dump (~17 MB, CDN names
  with and without dates both handled), parsed from DText into sections and
  stored incrementally in WAL SQLite — builds are resumable and idempotent,
  and only new or changed sections are embedded.
- Retrieval hygiene, verified against the live corpus: degenerate fragments
  and "link soup" chunks (bare URLs, `thumb #id` placeholders, site link
  lists) are excluded at import time and swept from the index on every build;
  artist/character/contributor/invalid category pages are pruned from the
  index while staying available for exact lookup; a query-time category
  filter over-fetched results keeps category drift from ever surfacing
  link-list pages. On the reference dataset this removed 5,932 junk chunks
  (80,481 → 74,549) and moved pose queries from modeler/VA stub pages to
  pages such as `hugging_from_behind` and `duo_focus`.
- Search enrichment no longer runs SQLite round-trips on the asyncio event
  loop (batched summary fetch in a worker thread), so a search cannot stall
  progress polling or health checks.
- The embedder gains `token_type_ids` synthesis for XLM-R tokenizers, keeping
  ONNX Runtime exports working out of the box.

## Chinese summaries

- The translate job produces structured summaries (`meaning` / `usage` /
  `pairing` / `notes` / related tags) per page, with three scopes (model
  vocabulary, popular tags by post count, all known tags), resumable runs and
  progress reporting. Online providers resolve exactly like the UI; a local
  GPU path (`scripts/translate_tag_wiki_local.py`, Qwen3-4B reference) is
  included for fully offline workflows.
- On the development machine the popular scope (post_count ≥ 1000) is fully
  covered: 9,057 summaries stored, 0 failures outstanding.

## Configuration

- New optional `[tag_wiki]` section in `config/app.toml`:
  `embed_model_repo` (point at a mirror or local repo id when Hugging Face is
  unreachable) and `min_post_count` (default threshold for the popular
  translate scope, surfaced to the UI through `/status`). See
  `docs/tag_wiki.md`, which now ships in the package.

## Reliability fixes folded into this release

- The Tag Wiki build panel stopped translate-progress polling only after the
  30-second aggregate status tick; the fine-grained poll now ends on its own
  response and refreshes the aggregate status when the job finishes.
- Lookup/search/ask responses are sequence-guarded, so a slow older response
  can no longer overwrite a newer query's result; numeric panel inputs clamp
  into the API-accepted range; error guidance (not-built, busy, tag-database,
  ask-unavailable, …) is shared across the page, drawer and build panel; tab
  panes carry full ARIA wiring with arrow-key navigation.
