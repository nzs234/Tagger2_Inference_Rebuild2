# Tagger2 V1.10 发布说明 / Release Notes

> 本说明为中英双语，各章节先中文、后英文。
> This document is bilingual: each section appears in Chinese first, followed by English.

V1.10 带来完全离线的 E621 标签百科（Tag Wiki）：本地镜像官方 wiki 页面，支持跨语言语义搜索、
高频标签的结构化中文摘要，以及基于已配置在线模型的检索增强问答（RAG）。同时，模型类资源不再
随发行包分发，改为首次使用时按指纹校验自动下载。Dataset Workflow 的固定上游基线不变。

V1.10 adds a fully offline E621 Tag Wiki: a local mirror of the official wiki pages with
cross-lingual semantic search, structured Chinese summaries for popular tags and
retrieval-augmented AI Q&A through the already-configured online providers. It also moves
model-class resources out of the release package: they now download automatically on first use with
fingerprint verification. The pinned Dataset Workflow baseline is unchanged.

## 新功能：本地 Tag Wiki 页面 / New: local Tag Wiki page (`/tag-wiki`)

- **查含义（Lookup）**：输入 tag 经别名归一后展示完整 wiki 页面——英文原文、结构化中文摘要、
  implications 搭配提示与相关 wiki 链接。标签管理器网格/标签药丸和工作台标签云的「查 Wiki」
  按钮会打开抽屉视图；标签管理器侧栏与展示栏新增直接查询表单。
  **Lookup** — a tag name resolves through alias normalization to the full wiki page: English
  sections, the structured Chinese summary, implied pairing tags and related wiki links. A drawer
  version opens from the tag manager grid/pills and the workbench tag cloud via the 查看 Wiki
  buttons, and both the tag manager sidebar and the display bar gained a direct wiki lookup form.
- **语义搜索（Search）**：中文或自然语言描述通过 `intfloat/multilingual-e5-small` ONNX 嵌入
  （384 维，`query:`/`passage:` 协议）与 SQLite FTS5 关键词检索做 RRF 融合命中英文语料；
  结果携带 wiki 依据、得分与推荐标签。
  **Search** — Chinese or natural-language descriptions hit the English corpus through
  `intfloat/multilingual-e5-small` ONNX embeddings (384-dim, `query:`/`passage:` protocol) fused
  with SQLite FTS5 keyword matches via Reciprocal Rank Fusion; results carry wiki evidence, scores
  and suggested tags.
- **AI 问答（Ask）**：检索到的章节与摘要作为上下文交给已配置的在线大模型（与打标通道相同的
  Provider）；回答必须引用 wiki 实际内容、只推荐检索资料中存在的标签。未配置 Provider 时展示
  熟悉的 409 引导状态而非直接失败。
  **Ask** — retrieved chunks plus summaries become grounded context for the configured online LLM
  (the same providers as the tagging channels); answers must cite what the wiki actually says and
  recommend tags that exist in the retrieved material. Without a configured provider the page shows
  the familiar 409 setup state instead of failing.

## 构建管线与数据卫生 / Build pipeline and data hygiene

- 数据来自 e621 官方 `db_export` 的 `wiki_pages` 每日导出（约 17 MB，兼容带日期与无日期两种
  CDN 命名），从 DText 解析为章节后增量存入 WAL SQLite——构建可恢复、可重复，只对新出现或
  变化的章节生成向量。
  Data comes from the official e621 `db_export` wiki dump (~17 MB; CDN names with and without dates
  both handled), parsed from DText into sections and stored incrementally in WAL SQLite — builds
  are resumable and idempotent, and only new or changed sections are embedded.
- 检索卫生（已在真实语料上验证）：退化碎片与「链接汤」章节（裸 URL、`thumb #编号` 占位符、
  站点链接列表）在导入时被剔除，并在每次构建时清理存量；artist/character/contributor/invalid
  类别页面的章节从索引中移除（页面保留供精确查询）；检索时还有一道基于类别的超量抓取过滤，
  类别漂移也不会把链接列表页推荐给用户。在参考数据集上，这清掉了 5,932 个垃圾章节
  （80,481 → 74,549），让姿势类查询从 modeler/VA 存根页转向 `hugging_from_behind`、
  `duo_focus` 等真实页面。
  Retrieval hygiene, verified against the live corpus: degenerate fragments and "link soup" chunks
  (bare URLs, `thumb #id` placeholders, site link lists) are excluded at import time and swept from
  the index on every build; artist/character/contributor/invalid category pages are pruned from the
  index while staying available for exact lookup; a query-time category filter over-fetched results
  keeps category drift from ever surfacing link-list pages. On the reference dataset this removed
  5,932 junk chunks (80,481 → 74,549) and moved pose queries from modeler/VA stub pages to pages
  such as `hugging_from_behind` and `duo_focus`.
- 检索后处理不再在 asyncio 事件循环上逐条查询 SQLite（按命中批量获取摘要并在工作线程中执行），
  搜索不会拖慢进度轮询或健康检查。
  Search enrichment no longer runs SQLite round-trips on the asyncio event loop (batched summary
  fetch in a worker thread), so a search cannot stall progress polling or health checks.
- 嵌入器为 XLM-R 分词器合成 `token_type_ids`，保证 ONNX Runtime 导出开箱即用。
  The embedder gains `token_type_ids` synthesis for XLM-R tokenizers, keeping ONNX Runtime exports
  working out of the box.

## 中文摘要 / Chinese summaries

- 翻译任务按页面生成结构化摘要（含义 / 用法 / 搭配 / 注意事项 / 相关标签），提供三种范围
  （模型词表、按 post_count 的高频标签、全部已知标签），支持断点续跑与进度展示。在线 Provider
  的解析方式与 UI 完全一致；本地 GPU 路径（`scripts/translate_tag_wiki_local.py`，参考实现为
  Qwen3-4B）面向完全离线工作流。
  The translate job produces structured summaries (`meaning` / `usage` / `pairing` / `notes` /
  related tags) per page, with three scopes (model vocabulary, popular tags by post count, all
  known tags), resumable runs and progress reporting. Online providers resolve exactly like the UI;
  a local GPU path (`scripts/translate_tag_wiki_local.py`, Qwen3-4B reference) is included for
  fully offline workflows.
- 在开发机上，高频范围（post_count ≥ 1000）已完全覆盖：9,057 条摘要入库，0 条失败残留。
  On the development machine the popular scope (post_count ≥ 1000) is fully covered: 9,057 summaries
  stored, 0 failures outstanding.

## 资源分发策略：模型类资源改为按需下载 / Resource distribution: model-class resources download on demand

- 发行包不再包含数据集分类快照与 Tokenizer 大文件（合计约 131 MB），只随包分发 manifest 与小型
  数据表，包体积从 46.8 MB 降至 25.3 MB。分类快照在标签数据库首次加载时后台下载，工作流执行与
  Token 检查在任务内按需下载——全部先做大小与 SHA-256 指纹校验再投入使用。
  The package no longer ships the dataset classification snapshots and the tokenizer pack
  (~131 MB combined): only manifests and small data tables ship, shrinking the package from
  46.8 MB to 25.3 MB. Classification snapshots download in the background when the tag database
  first loads; workflow execution and token checks fetch on demand inside the job — always
  size- and SHA-256-verified before use.
- 托管位置固定在 [resources-v1 发行页](https://github.com/nzs234/Tagger2_Inference_Rebuild2/releases/tag/resources-v1)；
  完全离线部署可用 `runtime\python.exe scripts\fetch_workflow_resources.py` 预取，或手动放置
  内容寻址文件。
  Hosting is pinned to the
  [resources-v1 release](https://github.com/nzs234/Tagger2_Inference_Rebuild2/releases/tag/resources-v1);
  fully offline deployments can pre-fetch with
  `runtime\python.exe scripts\fetch_workflow_resources.py` or place the content-addressed files
  manually.

  New optional `[tag_wiki]` section in `config/app.toml`: `embed_model_repo` (point at a mirror or
  local repo id when Hugging Face is unreachable) and `min_post_count` (default threshold for the

  `docs/tag_wiki.md`.

## 一并纳入的可靠性修复 / Reliability fixes folded into this release

- 构建面板的翻译进度轮询此前依赖 30 秒一次的聚合状态，任务结束后最多空转 30 秒；现在细粒度
  轮询在自己的响应不再是 running 时立即停止，并主动刷新聚合状态。
  The Tag Wiki build panel stopped translate-progress polling only after the 30-second aggregate
  status tick; the fine-grained poll now ends on its own response and refreshes the aggregate
  status when the job finishes.
- 查含义/搜索/问答响应加入序号守卫，慢的旧响应不会覆盖新的查询结果；数字输入按 API 允许范围
  钳制；错误引导（未构建、忙碌、标签库缺失、问答不可用等）在页面、抽屉与构建面板间统一；
  Tab 面板补齐 ARIA 关联并支持方向键切换。
  Lookup/search/ask responses are sequence-guarded, so a slow older response can no longer overwrite
  a newer query's result; numeric panel inputs clamp into the API-accepted range; error guidance
  (not-built, busy, tag-database, ask-unavailable, …) is shared across the page, drawer and build
  panel; tab panes carry full ARIA wiring with arrow-key navigation.
