# Tagger2 V1.10.4 发布说明

V1.10.4 将 Tag Wiki 首页整体重做为类似官方 booru Wiki 的高频标签目录：按官方分类与语义分组浏览、按标签名称/别名模糊搜索、点开词条查看中文摘要与可点击的关联标签。目录只收录 `post_count >= 100` 的高频标签，数据由维护端 CLI 生成，发行包与前端严格只读；原"语义检索 / AI 问答"三 Tab 流程从首页移除。

## 本轮功能范围

- **高频标签目录（schema v2）**：Wiki 数据库新增 `catalog_tags` / `catalog_relations` / `catalog_meta` 三张表（v1 老库打开即自动增量升级，页面/章节/向量/摘要不受影响）。e621 收录 49,891 个标签（235,561 条关系），Danbooru 收录 77,576 个标签（308,906 条关系），全部满足 `post_count >= 100`。
- **两级分类**：一级沿用官方 category（通用/角色/作品/物种/作者/元数据等）；`general` 类按确定性英语 token 规则 + overrides 划分二级语义组（外观与体型/动作与姿势/身体部位/服装服饰/性内容/其他通用）。规则纯静态可维护，无模型调用；修改规则需递增 `TAXONOMY_VERSION` 并重新生成目录。
- **模糊搜索**：`GET /catalog/tags?q=` 按固定优先级排序——精确名称 > 精确别名（经别名归一，标注原名）> 前缀 > 词前缀 > 包含；同级按 post_count 降序、名称升序，多词查询合并各词候选。搜索只命中目录内高频标签。
- **词条详情与关联标签**：`GET /catalog/tags/{title}` 返回标签信息（分类/分组/热度/中文译名）、原 Wiki 页（章节 + 中文摘要）与分组关联——隐含标签（implications，正/反向标注）、Wiki 页面关联（page_links）、共现（预留）。每个关联分组按目标热度排序后截断 30 条，枢纽标签（如 pokemon_(species) 的 800+ 关联）不会淹没页面；所有关联目标必然在目录内且可点击跳转。
- **维护端 CLI**：新增 `scripts/build_tag_wiki_catalog.py`（`--profile e621|danbooru|all`、`--min-post-count` 默认 100、`--dry-run`、`--status`），单事务整体重建目录并写入元数据；wiki 正文/向量/摘要永不被触碰。重建 wiki 语料或分类快照后、发行前必须重跑。
- **发行门禁**：`build_release.ps1` 打包阶段校验两个 staged 库的目录（表存在、非空、无低于 100 的标签、阈值达标、无目录外关系端点），冒烟测试对 frozen 成品包调用两个 profile 的 `/catalog/categories`；目录缺失或过低频直接终止打包。
- **前端重写**：Tag Wiki 页面改为目录浏览器——左侧分类侧栏、二级语义组筛选、60 个/页可翻页标签列表（中文译名/热度/Wiki 徽标）、300ms 防抖搜索（↑↓/Enter/Escape 键盘导航）、同页词条详情（返回列表后筛选保留）。只读状态面板保留；全部维护入口（构建/重建/翻译）仅存在于 CLI。
- **兼容性**：旧 `/lookup`、`/page`、`/search`、`/ask` API 已随向量检索与问答栈退役；当前目录接口在目录未生成时返回 409 `wiki_catalog_missing` 并带前端指引。

## 推荐的维护/分发流程

1. 维护机完成 Wiki 数据与中文摘要后，运行 `runtime\python.exe scripts\build_tag_wiki_catalog.py`（重建语料或分类快照后必须重跑）。
2. `scripts/build_release.ps1` 出包：自动快照两个 Wiki 库（含目录表）、校验目录完整性、强制包内 `frozen = true`，冒烟验证目录可用。
3. 发行页提供主包 zip；目录与已生成摘要随包提供，用户无需额外下载嵌入模型。

## 已知限制

- 共现关系（`cooccurrence` 分组）本版预留恒为空：官方 e621 `tags.csv` 的 `related_tags` 列与 Danbooru `/related_tag.json` 是后续接入点，本版关联仅用 implications + wiki 链接。
- 目录阈值 100 由发行门禁强制；维护端可用 `--min-post-count` 提高但不能低于 100。
- 旧 `/lookup`、`/page` 的 `related_tags` 保持原行为（不按频次过滤），以兼容既有消费者。
- Python 3.12；模型、`data_cache/`、OCR 运行时及缓存继续不随基础包提供；workflow 资源按 manifest 从 resources-v1 获取。发布包不包含用户数据、任务数据库、日志、令牌或密钥。

## 版本元数据

Python 包、前端 manifest 和 lockfile 根 package 均统一为 `1.10.4`。

## 验证说明

后端 pytest、Ruff、mypy、前端 Vitest、ESLint、TypeScript/Vite、Playwright 与发行冒烟（目录校验、双 profile `/catalog/categories`、frozen=true、双 Wiki 库存在）在本机通过；浏览器实测覆盖分类浏览、防抖搜索、词条详情、关联跳转、Escape 返回与 profile 切换。上游 checkout 未提供，仅验证 committed port manifest。Tag Manager 重构的专项验证见 `docs/tag_manager.md`。
