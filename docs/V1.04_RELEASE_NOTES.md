# Tagger2 V1.04 Release Notes

V1.04 adds a native, durable multi-provider image-generation workspace while
retaining the V1.03 Dataset Workflow compatibility baseline and data contracts.

## Image generation

- New first-class **Image Generation** page with responsive desktop/mobile UI.
- Google Gemini / Nano Banana native image requests, including model-aware
  aspect ratio, image size, reference count, sampling and candidate controls.
- OpenAI GPT Image generation/edit requests with size, quality, background,
  output format/compression, moderation and input-fidelity controls.
- xAI Grok Image support, plus explicit OpenAI-compatible images/chat routing
  for private gateways and newer models.
- Reference-image editing, authenticated previews/downloads, bounded parallel
  attempts, cancellation, retry, history search and confirmed deletion.

## Durability and security

- Image jobs use their own SQLite database and job workspace under
  `data/image_generation`; existing Tagger2 databases are not migrated.
- Every job freezes a non-secret Provider/capability snapshot and configuration
  digest. Digest drift, reference changes and artifact changes fail closed
  before a remote request or download.
- Completed artifacts survive restart and are not regenerated. Interrupted
  attempts return to a resumable state; user cancellation remains terminal.
- Provider JSON envelopes, Base64 payloads, downloaded images and served
  artifacts are bounded and content-validated.
- Provider/asset URLs retain DNS and SSRF validation with redirects disabled.
  Sensitive custom headers are excluded from persisted snapshots.
- API keys remain in the existing credential store and are never copied into
  image job configuration, public API payloads or browser URLs.

## Provider and UI changes

- Added an xAI / Grok Provider preset.
- Provider profiles now include image enablement, image capability family,
  optional image Base URL and image API style.
- Serializable image settings and the active job are restored after a browser
  refresh; reference `File` objects are intentionally never persisted.
- README and release-package documentation now include a complete model/route
  matrix, setup workflow, storage layout, security notes and troubleshooting.

## Upgrade notes

- Source checkouts can use `update.bat`; it only performs a clean fast-forward
  and never resets local work.
- Release ZIP installations should be extracted to a new directory. Move or
  reconfigure local `config`, `models`, `data_cache` and `data` content as
  described in the README.
- No configuration or history is imported from the standalone
  `gemini-image-webui` directory. Configure Providers once in Tagger2 so keys
  stay in the system credential store.
- Model IDs and account availability remain Provider-controlled. Unknown model
  IDs use conservative parameters unless the operator explicitly selects a
  compatible image capability family.

## Compatibility and validation

- Dataset Workflow still pins
  `lse14/e621-standard-capotion-workflow@ccc9d07497be637fc097c5da009d791f017144c9`.
- The release gate runs the complete backend suite, Ruff, mypy, frontend unit

- Exact source commit, upstream commit and completed gates are recorded in the
  packaged `VERSION.txt` and `VALIDATION_REPORT.json`.
