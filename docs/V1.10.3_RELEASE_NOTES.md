# Tagger2 V1.10.3 发布说明

V1.10.3 聚焦 Tag Wiki 语义检索的质量与分发模式：修复两处直接影响检索准确度的缺陷，将向量库整体升级到本地 Qwen3-Embedding-0.6B（ONNX，1024 维），并引入成品包只读（frozen）模式，使 Wiki 数据、中文摘要与向量全部由发布者构建完成后随包分发，最终用户开箱即用。

## 本轮功能范围

- **检索质量修复**：入库 passage 文本由 `tag 名 + 标题 + 正文` 组成（旧版正文不含 tag 名，跨语言查询缺少最强锚点）；`passage:` / `query:` 等模型前缀统一由 embedder 实现负责（修复旧版 e5 passage 前缀被重复拼接两次的问题）。两项修复显著改善中文查询 → 英文 wiki 正文的跨语言命中。
- **嵌入模型升级**：本地向量重建与查询 embedding 默认使用 `shawnw3i/Qwen3-Embedding-0.6B-ONNX`（1024 维，last-token pooling，与官方 Sentence Transformers pooling 配置一致）。embedder 现支持：Hugging Face 仓库根目录或 `onnx/` 子目录的 ONNX 权重（含 external data 分卷）自动下载、Qwen 风格导出所需的 `position_ids` 输入、按模型目录自动识别 pooling 模式与 nomic/e5 前缀。
- **维护端重建后端**：新增 OpenAI 兼容远程 embedder（`embed_backend = "openai"`，适配 LM Studio `/v1/embeddings`），维护机可用本地 GPU 服务快速重建向量；响应按 `index` 排序、断连重试、远程不可用不缓存失败。新增 `scripts/reembed_tag_wiki.py`：跳过 dump 流水线、对两个库直接全量重嵌并输出进度（GPU 上约 300–420 chunks/s）。
- **成品包只读模式（frozen）**：`[tag_wiki] frozen = true` 时后端 `/build` 与 `/translate` 返回 403（code `wiki_frozen`），前端构建面板隐藏全部维护入口并提示数据已内置；`GET /status` 暴露顶层 `frozen` 与 `index.embedding_backend`。发行脚本在打包阶段强制把包内 `config/app.toml` 置为 `frozen = true`，开发机本地配置不受影响。
- **发行包内容调整**：基础包继续包含两个 Wiki SQLite 快照（本版起为 1024 维向量），并随包携带嵌入模型的 tokenizer/config 文件；多 GB 的 `model.onnx` 权重不进主包（GitHub 单资产 2GB 上限），作为发行页单独资产提供，用户下载后放入 `data/tag_wiki/models/shawnw3i__Qwen3-Embedding-0.6B-ONNX/model.onnx` 即启用本地语义检索。冒烟测试新增断言：包内 frozen=true、tokenizer 文件齐全、权重未误入主包。
- **测试**：新增 OpenAI 兼容 embedder 单元测试（模型自动解析、批次顺序/归一化、按模型族的前缀、维度探测、错误路径）、frozen 模式拒绝构建/翻译的服务级测试、passage 文本组装回归测试。两个 provider 契约测试显式开启 `allow_local_providers`：其测试对象是 CRUD/发现语义而非 URL 策略，且开发机处于 fake-ip DNS（198.18.0.0/15）时公网域名也会被解析为本地地址。

## 推荐的维护/分发流程

1. 维护机 `config/app.toml`：`embed_backend = "local"`、`embed_model_repo = "shawnw3i/Qwen3-Embedding-0.6B-ONNX"`、`frozen = false`（本地开发默认值）。
2. Wiki 数据/翻译/向量全部在维护机完成：dump 导入、中文摘要翻译、`scripts/reembed_tag_wiki.py` 全量重嵌（模型更换后必须重嵌并核对 `index.dimension`）。
3. 运行 `scripts/build_release.ps1` 出包：脚本自动快照两个 Wiki 库、随包写入 tokenizer/config、强制包内 `frozen = true`，并校验权重未进主包。
4. 发行页同时提供主包 zip 与 `Tagger2_Qwen3-Embedding-0.6B-ONNX_model.onnx`（附 sha256）；用户放置该文件后语义检索完全本地、离线可用。

## 兼容性与限制

- 旧数据库（384 维 e5 向量）与新代码不兼容：升级后需用新模型重新向量化（构建面板勾选"强制重新向量化"或使用重嵌脚本）。
- 用户端未放置 `model.onnx` 权重时，语义检索不可用，搜索自动退化为关键词模式并在状态接口明确显示模型未就绪；frozen 模式下不会在用户机器上触发模型下载。
- 纯中文查询的关键词腿（FTS5 默认分词）基本无效，检索实际依赖向量腿；个别抽象查询（如"女仆装"）命中率一般，后续可通过查询侧轻量翻译或中文分词继续改进。
- Python 要求为 3.12；前端依赖使用锁定的 npm lockfile。模型、`data_cache/`、OCR 运行时及其缓存继续不随基础包提供；workflow 资源按 manifest 从 resources-v1 获取。
- 发布包不包含用户数据、任务数据库、日志、令牌或密钥。ZIP 用户应从新版 Releases 获取更新并迁移本地配置、模型、缓存和数据目录。
