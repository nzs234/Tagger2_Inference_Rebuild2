# Tagger2 V1.10.1 发布说明

V1.10.1 把 Danbooru 标签百科补齐到与 e621 同等的水平：Danbooru 没有官方打包导出，
语料通过官方 JSON API 全量抓取（21.6 万页 / 25.6 万章节），完成 e5 向量索引并接入
Tag Wiki 的全部三种查询模式。同时，**两个构建完成的 Wiki 数据库自本版本起随发行包
分发**——解压即可使用，无需自行重建语料与索引。

## 新功能：Danbooru wiki 语料库

- 语料抓取：Danbooru 无 `db_export`，wiki 页面通过官方 JSON API 分页抓取（每页最多
  1000 条，`page=b<id>` 游标不依赖服务端排序）。抓取器对上游保持克制：请求间隔
  2 秒、`429` 遵循 `Retry-After`、瞬时失败指数退避；批次实时落盘断点，中断重跑即续传。
  全量 280 个请求拉回 278,625 页，其中 216,356 页入库（其余为站点自动创建的空占位页），
  解析后得到 320,390 个章节；退化碎片与「链接汤」章节在导入时剔除。
- 向量索引：解析得到 320,390 个章节，e5 嵌入后按类别剪枝不可检索页面
  （画师 / 角色 / 摄影者等，约 17.9 万章节），最终索引 **140,965 个章节**；
  页面本身保留供精确查询。
- 查询接线：Tag Wiki 页面新增 **e621 / Danbooru 语料库切换**，查含义、中文语义搜索
  与 AI 问答（RAG）都按 profile 走各自的库；标签管理器与工作台的「查 Wiki」抽屉
  跟随当前会话的语料库（e621 会话查 e621、danbooru 会话查 danbooru）。
- 命令行：`scripts/build_tag_wiki.py --profile danbooru --build` 只刷新剪枝与向量索引
  （无需重新抓取）；`scripts/build_tag_wiki.py --translate` 支持为 danbooru 页面
  预翻译中文摘要（本包未预置 danbooru 摘要，可在构建面板按范围分批翻译）。

## 分类快照改为官方全量数据

- 此前 danbooru 分类快照来自 tagcomplete 社区词表（约 14 万条，面向打标模型词表），
  覆盖不了 wiki 语料：大量页面无法归类，剪枝与查含义的分类信息失真。
- 新增 `scripts/fetch_danbooru_classification.py`：通过官方 API 抓取全量 tags
  （post_count ≥ 1，共 1,076,994 条）、active 别名与 implications，输出
  e621 db_export 风格的 CSV，经既有导入管线注册为新的 `classify-danbooru-*`
  快照资源。TagDatabase 自动选用同 profile 下最新的快照，无需改配置。
  分类覆盖补全后，剪枝能正确移除画师 / 角色等页面的章节，中文语义搜索不再被
  冷门角色介绍页占据。
- 本包内置的 danbooru 快照即为官方 API 全量数据；e621 快照不受影响。

## Wiki 数据库随包发行

- `data/tag_wiki/` 下的两个构建完成数据库自本版本起随包分发：
  - `tag_wiki.sqlite3`（e621 镜像：页面 / 章节 / 向量 / 9,057 条中文摘要）
  - `tag_wiki_danbooru.sqlite3`（danbooru 镜像：页面 / 章节 / 向量）
- 打包时通过 SQLite `VACUUM INTO` 生成自包含、紧凑的快照
  （`scripts/snapshot_wiki_databases.py`），即使应用正在使用数据库也能一致复制；
  解压即用，无需重建。跨语言嵌入模型（约 470 MB）仍属模型类大文件，首次构建时
  按需下载，不随包。

## 一并纳入

- `WikiStore` 新增批量写入路径（单事务多页面）、按标题批量快照查询与整页删除
  （上游删除的 wiki 页面会从本地镜像中同步清除）。
- Wiki 构建状态与翻译状态携带 profile 标记；`/status` 返回各语料库独立的
  数据库 / 索引视图（顶层字段保留 e621 视图以兼容旧客户端）。
