# Tagger2 V1.06.1 Release Notes

V1.06.1 is a feature patch for the V1.06 release. Tags that the offline
Chinese dictionaries miss can now be translated on demand in the tag manager
with the configured online model, and every on-demand translation is saved to
a local user dictionary so it never needs translating again — including
offline and after a restart. The pinned Dataset Workflow baseline is
unchanged.

## New: on-demand tag translation with local persistence

- The tag manager toolbar (above the image grid) and the editor drawer show an
  在线翻译缺失标签 (N) button whenever visible tags have no Chinese name: N
  covers the current page or the open image. Clicking sends only the tags the
  offline dictionary misses to `POST /tag-manager/translations/translate`
  (request cap 200 tags, model calls chunked at 40 per call), so dictionary
  hits never cost tokens.
- The model is asked for a JSON tag→translation mapping; English echoes,
  oversized values and unusable replies are dropped. Results render
  immediately across the grid cards, editor pills, stats and autocomplete
  (a session-local memory store bridges already-rendered views), and are
  persisted atomically to
  `data/tag_manager/translations/{profile}-zh.csv`.
- That user dictionary is merged over the shipped one on load (user entries
  win), so saved translations resolve offline, survive restarts, and are not
  touched by regenerating the shipped dictionaries. Sources and file layout
  are documented in `resources/tag_translations/README.md`.
- Setup and failure states mirror NL translation: with no enabled provider
  holding a credential the route answers `409 tag_translate_unavailable`;
  model failures answer `502 tag_translate_failed` (retryable).
- Fixed in passing: the V1.06 package-lock pinned the `lz-string` dependency
  with a wrong version field (the resolved tarball and integrity were always
  1.5.0); the lockfile now agrees with what it resolves.
